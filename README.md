# YOLO Traffic Tracking

Track vehicles and pedestrians in recorded traffic intersection video with
Ultralytics YOLO11 and BoT-SORT.

The primary output is structured trajectory data for downstream traffic analysis.
The annotated video is written as a sanity-check artifact only.

## Setup

```bash
uv sync
```

## Usage

Run on Apple Silicon with the default `mps` device:

```bash
uv run traffic-track path/to/intersection.mp4
```

By default, outputs are written to `outputs/<input-video-stem>/`. To choose a
different output directory, pass it after the video path:

```bash
uv run traffic-track path/to/intersection.mp4 outputs/intersection_run
```

Run on a CUDA machine using GPU `0`:

```bash
uv run traffic-track path/to/intersection.mp4 --device 0
```

Run on CPU:

```bash
uv run traffic-track path/to/intersection.mp4 --device cpu
```

The default tracked COCO classes are `person`, `bicycle`, `car`, `motorcycle`,
`bus`, and `truck`, represented by IDs `0,1,2,3,5,7`. Override them with:

```bash
uv run traffic-track path/to/intersection.mp4 --classes 2,5,7
```

`summary.txt` filters out very short-lived tracks by default and counts only
tracks with at least 5 detections. Override that threshold with:

```bash
uv run traffic-track path/to/intersection.mp4 --min-summary-detections 10
```

## Outputs

Each run writes the following files to the output directory:

- `tracks.csv`: one row per tracked detection with frame index, timestamp,
  track ID, class, confidence, and pixel-space `x,y,w,h` bounding box values.
- `track_summary.csv`: one row per track with first and last frame, first and
  last timestamp, majority class name, and detection count.
- `summary.txt`: console-style summary with total tracks, duration, per-class
  track counts, and the minimum-detections filter used for those counts.
- `annotated.mp4`: annotated video generated by Ultralytics `save=True`.

## ReID dataset prep

Export one JPEG crop per vehicle track for a ReID gallery. Video helpers stay
under `utilities/` (`trim-video`); ReID prep lives in `tools/`
(`export-reid-thumbs`, `prepare-reid-batch`).

### Single camera

Demo smoke test on a short IntersectionOne clip:

```bash
uv run trim-video /mnt/nvme1n1p1/data/carreid/IntersectionOne/20210109_122809M.MP4 0 30 -o trimmed/demo

uv run traffic-track \
  trimmed/demo/20210109_122809M_trim_00h00m00s-00h00m30s/20210109_122809M_trim_00h00m00s-00h00m30s.MP4 \
  outputs/demo_IntersectionOne \
  --classes 2,3,5,7 --device 0 --conf 0.05

uv run export-reid-thumbs \
  --tracks outputs/demo_IntersectionOne/tracks.csv \
  --video trimmed/demo/20210109_122809M_trim_00h00m00s-00h00m30s/20210109_122809M_trim_00h00m00s-00h00m30s.MP4 \
  --camera-name IntersectionOne \
  --output-dir data/reid/demo
```

### Batch (multi-intersection)

List one row per camera/intersection in a jobs CSV (`camera_name,video`), then run
track + export for all of them into one shared gallery:

```bash
# See data/reid/jobs.example.csv for the column format.
uv run prepare-reid-batch \
  --jobs data/reid/jobs.example.csv \
  --output-dir data/reid/demo \
  --device 0 --conf 0.05 --classes 2,3,5,7
```

Outputs:

- `data/reid/demo/thumbs/` — AIC-style `{Camera}_{videoStem}_{trackId}.jpg` from every job
- `data/reid/demo/manifest.csv` — combined rows for all cameras (not overwritten per job)
- `outputs/reid/{camera_name}/` — per-camera `tracks.csv` and tracking artifacts

Reuse existing tracks without re-running YOLO:

```bash
uv run prepare-reid-batch --jobs data/reid/jobs.example.csv --skip-track
```

Distant traffic-cam footage often needs a lower `--conf` than the tracking
default of `0.25`. If YOLO detects cars but `tracks.csv` stays empty, BoT-SORT
did not assign track IDs — try adjusting `--conf` or using a clearer clip.
